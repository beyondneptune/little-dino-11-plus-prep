# Phase 2 report — automated verification system (autonomous run 1)

Written in place of a parent checkpoint (autonomous mode). Phase 2's verification
**core** is built and tested; the language blind-solve pipeline is the remaining
piece and is deliberately deferred until its usage cost is measured.

## Built and tested
- **Typed question schema** (`scripts/qschema.py`): every field needed to
  reproduce an item (generator + version + seed), plus a verification record of
  checks that can fail.
- **Serve gate** — the single chokepoint that enforces "nothing unverified
  reaches a child": an item serves only if `status==auto_approved`, its
  verification validates, and structure is sane (re-checked at serve time so a
  tampered record can't slip through). 10 hand-worked tests prove draft /
  unverified / failed-check / tampered / duplicate-option / bad-level items are
  all blocked.
- **Computable verification** (`scripts/verify_computable.py`): generated item →
  **independent** solver (`testers.py`, separate logic) → record → gate. A planted
  wrong key, a duplicate option, and a wrong NVR key are all rejected.
- **Planted-bug corpus + catch rates** (`scripts/planted_corpus.py`): for every
  deterministic verifier, each planted flaw (wrong key, duplicate option, synonym
  distractor, real-word misspelling, ambiguous grammar) is caught **100%**, with
  **0** genuine items wrongly rejected (full report: `reports/catch_rates_2026-11-14.md`).
  Guarded by a test so any drop fails the build.
- **Age-1 level definitions 1-5** (`content/levels/age1.yaml`): all 35 Age-1
  topics with number-size / vocabulary / rule-complexity bands, a reading-grade
  ceiling, per-level focus and a per-topic list of the mistakes children actually
  make (for distractors).

## What is NOT yet built (and why)
- **Language verification for R topics** (comprehension, vocabulary-in-context,
  cloze, literary technique). The brief requires 3+ independent *blind solves*
  (no answer key) plus an adversarial second-answer search. That needs LLM calls;
  per the prompt, their usage cost must be measured and recorded before they run.
  Until it exists and its catch rate is measured, **all R topics stay
  `not_served`** — they are never shown to a child. This is the safe default.
- The child-facing app (Phase 4) and the Age-1 content banks (Phase 3).

## What the automated checks CANNOT catch (honest limits)
- The deterministic verifiers prove a computed answer is correct and unique; they
  do **not** judge whether a question is *interesting* or pitched at the right
  level — the level definitions guide that, but it is a human-style judgement.
- They cannot yet verify language/meaning items (that is the pending pipeline).
- A fact card's facts have two agreeing sources, but "agree" was judged during
  research, not by an automated semantic check.
